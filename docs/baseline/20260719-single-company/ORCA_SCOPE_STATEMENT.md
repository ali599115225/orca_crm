# ORCA SCOPE STATEMENT
**Document ID:** ORCA-SCOPE-001
**Version:** 1.0
**Date:** 2026-07-19
**Status:** `APPROVED BASELINE`
## 1. داخل النطاق
- منصة تشغيل داخلية لشركة واحدة.
- إدارة المستخدمين الداخليين والأدوار والصلاحيات.
- تأسيس الإدارات والفروع وفرق العمل ونطاقات الوصول.
- العملاء المحتملون، جهات الاتصال، المشاريع، الوحدات والعقارات.
- الجولات والعروض والفرص والعقود وخطط الدفع والأقساط والفواتير والمدفوعات التشغيلية الخاصة بأعمال الشركة.
- المهام والصيانة والمستندات وسجل التدقيق.
- التقارير ولوحات التشغيل والوكلاء الداخليين.
- مسارات تكامل جاهزة فنيًا مع Providers خارجيين، دون حسابات إنتاجية ضمن التسليم.
- Mock/Sandbox tests والتحقق من Webhook signatures وحالات الانقطاع والاستعادة.
- CI/CD وPreview والمراقبة والنسخ الاحتياطي وخطط الاستعادة.
## 2. خارج النطاق
- تأجير ORCA لشركات مستقلة أو تشغيل SaaS متعدد الشركات.
- تسجيل شركات أو مستأجرين جدد ذاتيًا.
- باقات SaaS وترقيات ودفع اشتراك للشركات أو شراء إضافات.
- بوابة Platform Owner لإدارة عملاء SaaS.
- توفير أو شراء حسابات WhatsApp/Meta أو Email/SMTP أو دفع أو SMS أو تخزين أو إعلانات أو خرائط.
- تقديم أو افتراض تراخيص عقارية أو مالية أو إعلانية أو اتصالات أو ZATCA أو Ejar دون وثيقة رسمية.
- استخدام حسابات أو أرقام أو مفاتيح المطور.
- إرسال أو دفع أو استرداد أو رفع خارجي حقيقي ضمن اختبارات الإغلاق.
## 3. داخل النطاق الانتقالي فقط
العناصر التالية تبقى مؤقتًا لمنع كسر البيانات والتشغيل، لكنها ليست جزءًا من النموذج المستهدف:
- جدول `Tenant` وحقل `tenantId`.
- subdomain والـwildcard routing الحالي.
- حقول subscription/billing في قاعدة البيانات.
- نماذج Provider المربوطة بـ`tenantId`.
تعامل هذه العناصر كطبقة توافق تمثل الشركة الواحدة إلى أن تكتمل خطة الانتقال.
## 4. مخرجات المرحلة الحالية
1. حزمة وثائق حاكمة.
2. Conflict Register شامل.
3. Impact Assessment قبل أي تحويل معماري.
4. خطة بيانات وتوافق وتراجع/Forward-Fix.
5. قائمة إصلاحات P0/P1 قابلة للاختبار.
6. فرع تنفيذ مستقل وPR وPreview بعد فتح قناة GitHub App.
## 5. افتراضات ممنوعة
- لا نفترض وجود أكثر من شركة تشغيلية.
- لا نفترض وجود ترخيص أو حساب مزود.
- لا نفترض أن وجود Adapter يعني اتصالًا فعليًا.
- لا نفترض أن نجاح Health endpoint يعني جاهزية كل Cron أو Migration.
- لا نفترض أن تقريرًا قديمًا يثبت حالة Runtime الحالية.
