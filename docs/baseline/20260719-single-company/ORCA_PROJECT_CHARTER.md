## 1. هوية المشروع
ORCA منصة تشغيل داخلية مملوكة ومشغلة بواسطة شركة مستقلة واحدة. مستخدموها موظفو الشركة ووكلاؤها ومديروها ومحاسبوها ومستخدموها الداخليون.
- **مالك ومشغل المنصة:** الشركة المستقلة المالكة لـ ORCA.
- **مطور ومقدم الخدمة التقنية:** يبني ويصلح ويوثق المنصة ومسارات التكامل، ولا يوفر حسابات أو تراخيص أو بيانات اعتماد لمزودين خارجيين.
- **النموذج التجاري المعتمد:** `VERIFIED — SINGLE INDEPENDENT COMPANY`.
- **SaaS متعدد الشركات:** `OUT OF SCOPE`.
## 2. الغرض
توفير منصة داخلية موثوقة لإدارة العمليات العقارية للشركة الواحدة، تشمل العملاء المحتملين والمشاريع والعقارات والجولات والعروض والعقود والتحصيل والمهام والمستندات والتواصل والتقارير والوكلاء الداخليين، ضمن صلاحيات وأدوار وإدارات وفروع وفرق عمل واضحة.
## 3. أهداف المرحلة الحالية
1. تثبيت خط أساس واحد قائم على أدلة GitHub والكود وRuntime.
2. كشف وتصنيف بقايا التصميم SaaS/Multi-Tenant دون حذفها تلقائيًا.
3. حماية البيانات عبر إبقاء `tenantId` مؤقتًا كنطاق الشركة الواحدة.
4. تأسيس RBAC وعزل تنظيمي داخلي قابل للتطبيق على الخادم.
5. جعل التكاملات Integration-Ready مع حالة `NOT CONFIGURED` آمنة وطبيعية.
6. معالجة موانع البناء والأمن والتشغيل قبل التجميع والإطلاق.
7. إنشاء مسار انتقال آمن قابل للتراجع أو Forward-Fix دون فقد بيانات.
## 4. أصحاب المصلحة
| الطرف | المسؤولية |

| مالك الشركة المشغلة | القرارات التجارية والقانونية والتراخيص وحسابات المزودين وبيانات الاعتماد والموافقات على العمليات الحقيقية |
| مقدم الخدمة التقنية | المعمارية والكود والاختبارات والتوثيق وواجهات الربط والـAdapters والـWebhooks وحالات الفشل |

| المستخدمون الداخليون | استخدام المنصة ضمن الدور والنطاق التنظيمي المعتمد |
## 5. مبادئ الحوكمة
- الدليل يتفوق على الادعاء التاريخي.
- لا Migration أو حذف بيانات دون خطة أثر وبيانات وتوافق وتراجع واختبارات عدم فقد.
- لا إرسال أو دفع أو استرداد أو اتصال حقيقي دون موافقة صريحة وبيانات الشركة.
- لا استخدام لبيانات المطور في تشغيل التكاملات.
- لا تعديل مباشر على `main`.
- كل إصلاح يمر باختبار مستهدف، Build، Preview، ثم PR.
## 6. معايير النجاح
- لا يوجد مسار عام لتسجيل شركة/مستأجر جديد ضمن المنتج الحالي.
- لا تظهر باقات أو فواتير اشتراك SaaS للشركات في الواجهة الداخلية.
- جميع العمليات الحساسة محمية بجلسة نشطة، مستخدم فعال، دور قاعدة بيانات، ونطاق تنظيمي.
- `NOT CONFIGURED` لا يعطل بقية المنصة ولا يولد بيانات وهمية.
- جميع Preview builds ناجحة قبل الدمج.
- لا يوجد انحراف Schema غير موثق في Production.
- لا تدعي المنصة ترخيصًا أو اتصالًا أو امتثالًا غير مثبت.
## 7. بوابات التوقف
يتوقف التنفيذ عند: Migration مدمرة، أثر محتمل على بيانات Production، كشف/تدوير Secret، عملية مالية أو إرسال حقيقي، أو قرار قانوني/تجاري يحتاج المالك.
